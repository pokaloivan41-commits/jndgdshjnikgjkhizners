# Развёртывание GiftOffer на Railway

> Инструкция для Docker-проекта. Основной бот (`BOT_TOKEN`) обслуживает профильные офферы через Telegram Connected Bots over MTProto, баланс и админку; второй бот (`GROUP_BOT_TOKEN`) — только групповые функции. Оффер отправляется командой `/offer` прямо в целевом личном чате; оба бота используют одну SQLite-базу.

## Важно про «бесплатно»

По актуальной документации Railway, новый аккаунт получает пробный кредит $5 на срок до 30 дней, а затем план Free даёт $1 кредита на использование в месяц. На Free указаны лимиты 0.5 GB RAM, 1 vCPU, одна replica и 0.5 GB volume. Для постоянно работающего бота этого кредита может не хватить: следи за Usage/Billing, иначе Railway может остановить сервис. [Тарифы Railway](https://docs.railway.com/pricing/plans) · [Free Trial](https://docs.railway.com/pricing/free-trial)

## 1. Подготовь репозиторий GitHub

1. Распакуй архив `GiftOffer-v2.14-simple-admin.zip`.
2. Создай **private** repository на GitHub.
3. Загрузи в корень репозитория содержимое папки проекта: в корне должны лежать `Dockerfile`, `requirements.txt` и `bot.py`.
4. **Не добавляй** `.env`, базу SQLite, `data/`, `logs/` или токены. `.gitignore` уже настроен для локальных секретов и данных.

Railway умеет собирать репозиторий по `Dockerfile`; для базы из Docker Compose Railway предлагает отдельные Services и Railway Volumes. [Руководство Railway по Docker Compose](https://docs.railway.com/guides/docker-compose)

## 2. Создай Service в Railway

1. Войди на [railway.com](https://railway.com/) через GitHub.
2. Нажми **New Project → Deploy from GitHub Repo** и выбери private repository с ботом.
3. Если Railway спросит доступ к GitHub, разреши доступ к этому репозиторию.
4. Для сервиса оставь Dockerfile в корне. Проект уже содержит `Dockerfile` с запуском `python bot.py`; для long polling-бота публичный домен и отдельный web-сервис не требуются.
5. Дождись первой сборки. Если деплой остановится из-за пустых переменных — задай их в следующем шаге и запусти **Redeploy**.

## 3. Добавь переменные сервиса

Открой Service → **Variables** → **New Variable**. Для каждой переменной укажи отдельно имя и значение — не вставляй весь `.env` одним текстом.

Обязательные:

| Name | Value |
|---|---|
| `BOT_TOKEN` | Новый токен от @BotFather. Вводи его только в Railway Variables, не в GitHub и не в чат. |
| `ADMIN_IDS` | Твой числовой Telegram ID, например `123456789`; не username. Несколько ID можно разделить запятыми. |
| `STAR_RECEIVE_USERNAME` | Username получателя Stars без `@`, например `walooon`. |
| `DATABASE_PATH` | `/app/data/offers.sqlite3` |

Остальные можно задать явно (или оставить встроенные значения проекта):

| Name | Value |
|---|---|
| `USDT_PER_STAR` | Оставь `0` на первом запуске; курс можно будет удобно задать из админ-панели командой `/rate` |
| `CRYPTOPAY_TOKEN` | Токен приложения Crypto Pay; храни только в Railway Variables, не присылай в чат |
| `GROUP_BOT_TOKEN` | Токен второго, отдельного бота для групповых команд и бонуса. |
| `MTPROTO_API_ID` | Числовой API ID приложения с [my.telegram.org](https://my.telegram.org); нужен подключению профиля. |
| `MTPROTO_API_HASH` | API hash с my.telegram.org; храни только в Railway Variables как секрет. |
| `BONUS_GROUP_ID` | Необязательно: отрицательный ID группы вида `-100...`; требуется только для групповых бонусов и лидербордов. Добавь группового бота администратором; право удалять сообщения нужно для автоудаления временных ответов. |
| Subscription plans | Seeded in SQLite on first boot; edit prices, days and daily quotas in **Admin → Plans & quotas** |
| `OFFER_TTL_HOURS` | `48` |
| `BACKUP_RETENTION_DAYS` | `7` |
| `PUBLIC_BASE_URL` | Не требуется для профильных `/offer`: Telegram строит native preview по ссылке `t.me/nft`; оставь пустым, если не используешь legacy image endpoint |

Не публикуй токен в репозитории. Если реальный токен уже отправлялся в чат или попал в публичный репозиторий, отзови его в @BotFather и создай новый.

## 4. Подключи постоянное хранилище для SQLite

Без Volume файл базы на контейнере может потеряться при пересборке или замене контейнера.

1. Открой сервис → **Settings → Volumes → Add Volume**.
2. Укажи **Mount Path**: `/app/data`.
3. Проверь, что переменная `DATABASE_PATH` равна `/app/data/offers.sqlite3`.

В базе хранятся выбранный курс Crypto Pay, лимиты, цена/длительность подписки, настройки и резерв группового бонуса, пауза новых офферов, кэш NFT и подключения профилей. MTProto session-файл Offers-бота также создаётся в `/app/data`; он содержит авторизационные данные и должен оставаться приватным. Постоянный Volume сохраняет базу, session-файл и кэш между redeploy; настройки из админки имеют приоритет над исходными переменными окружения. [Документация Railway Volumes](https://docs.railway.com/volumes)

## 5. Запусти и проверь

1. Открой **Deployments** сервиса и выбери **Deploy** или **Redeploy**.
2. В **Logs** дождись строки примерно `Connected to Telegram as @ИмяБота`.
3. Напиши боту `/start`, затем `/admin` с аккаунта, чей ID внесён в `ADMIN_IDS`.
4. В **🧾 Тарифы и квоты парсера** меняются цены, сроки и дневные квоты парсера; число офферов не ограничено. В **⚙️ Настройках сервиса** меняются срок оффера, пауза и Crypto Pay. Для курса используй меню **💎 Crypto Pay / курс**; `/rate 100 1.50` — только пример.
5. В @BotFather включи для основного оффер-бота возможность подключения как connected/business bot (это флаг самого бота, а не требование Business-аккаунта владельца профиля). Убедись, что заданы `MTPROTO_API_ID` и `MTPROTO_API_HASH`, затем на тестовом профиле подключи Offers-бота через **Настройки → Автоматизация чатов** и разреши отвечать в выбранном личном чате. Проверь `/offer https://t.me/nft/Example-123 1`, native preview, кнопки «⊗ Отклонить»/«✓ Принять» и общий баланс. Для приёмки используй тестовый аккаунт; не передавай реальный NFT и не делай реальную выплату.
6. Проверь, что Volume содержит `/app/data/offers.sqlite3` и кэш `/app/data/nft_photos`; после redeploy фото-кэш не должен теряться.
7. Проверь Usage/Billing через день и через неделю. Бесплатный кредит ограничен и не является обещанием круглосуточной работы.

### Важно: одна работающая копия

Оставь для бота **одну replica** и не запускай тот же токен одновременно на Railway и локальном компьютере. Telegram long polling не рассчитан на несколько одновременно работающих экземпляров одного бота: это может вызывать ошибки `Conflict` и прерывать получение обновлений. SQLite тоже рассчитана на один экземпляр этого бота.

## Если бот не запускается

- Ошибка о пустом `BOT_TOKEN` — переменная не добавлена, задана под неверным именем или сохранена с лишними пробелами.
- Telegram отвечает `Unauthorized` — токен неверный или отозван; создай новый через @BotFather и замени Railway Variable.
- Ошибка `Conflict: terminated by other getUpdates request` — выключи локальный запуск и старые Railway deployments; оставь один активный экземпляр.
- Бот запускается, но данные пропадают после redeploy — проверь Volume `/app/data` и `DATABASE_PATH=/app/data/offers.sqlite3`.
- Если Railway исчерпал Free usage credit, проверь Usage/Billing; для постоянного 24/7 запуска может потребоваться платный план или другой хостинг.
